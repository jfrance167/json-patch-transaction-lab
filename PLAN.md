## Pointer and six-operation semantics

Use plain pointers only: empty string addresses root; otherwise initial slash; empty member names permitted; validate tilde escapes then decode `~1` before `~0`, once. No fragment/percent decoding. Objects use exact decoded names, including numeric-looking names and `-`. Arrays require ASCII `0` or nonzero-leading digits; reject signs, leading zeros, Unicode digits and whitespace. Compare textual index bounds before int conversion. Scalars cannot be traversed. `-` is permitted only as the final array destination of add, or add-like copy/move; never as a source/existing array element. Intermediate `-` cannot traverse an array.

Operation requirements: every object has string op and meaningful string path; add/replace/test require value (null is a supplied value); copy/move require string from. Unrecognized members are ignored semantically after complete admission. An unused `from` on add, for example, is ordinary admitted data rather than an interpreted pointer. No generated diff, custom operations or URI/reference resolution.

| Operation | Profile behavior |
|---|---|
| add | Root replaces any value. Existing object parent required; insert/replace final member. Existing array parent required; insert at0..length or append `-`; shift following elements. Never create missing parents. Clone supplied value. |
| remove | Existing non-root member/element required; array shifts left. Root remove excluded before execution because this profile always retains a JSON result. Explicit subset limitation, not a universal RFC ruling. |
| replace | Existing target required, root always exists even when null/false/zero; clone supplied value. Array index must be below length. |
| test | Existing target required; recursive JSON type-aware equality. Booleans differ from numbers; integer equality is numerical within integer-only subset. Object key order irrelevant; array order significant; exact string code points. No mutation. |
| copy | Resolve current source, including root; take detached snapshot before add-like destination evaluation. Copy root into child can succeed without cycles. Copies have no shared mutable containers with source or input. |
| move | Existing current source required. Reject decoded source token sequence as proper prefix of destination (not raw string prefix). Equal decoded paths are successful no-ops only after source existence. Otherwise remove then evaluate destination against post-removal state and add. Non-root source to root supported; root to descendant prohibited; root-to-root no-op supported. |

Ordered operations run against the previous accepted working state. A missing source, missing destination parent/target, invalid array index, out-of-range index, scalar traversal, descendant move or unequal test rejects the entire patch. A failed move destination after removal never publishes a partial result. Stop executing after first failure; remaining trace entries are not-run. Empty patch succeeds unchanged. Success can be unchanged even after a change/restoration sequence.
